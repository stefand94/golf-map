## GOLF-116 — Costs tab: one line per hotel stay · blocker · M

### Problem
A hotel used across multiple nights or on two separate days renders as one
line **per night / per day** on the Costs tab, so a 2-night stay shows as
two lines. The breakdown is wrong (the grand total is fine).

### Requirement
- Group hotel line items in the Costs breakdown by **`stayId`** (fall back
  to `name` + rounded lat/lng when `stayId` is missing on older trips).
- Sum `nights` across the grouped items.
- Render one line per stay in the form:
  `Hotel A (£300/night × 3 nights) — £900`
  (use the trip's existing currency formatting; SA trips show `R`).
- Respect `priceType`: only multiply by nights when the price is
  per-night. If `priceType` is a flat/total price, show
  `Hotel A (£900 total) — £900` and do **not** multiply.
- Golf and POI lines are unaffected.
- The trip grand total must not change in value — only the hotel breakdown
  is regrouped.

### Where
- Costs-tab render + cost calc: `js/trip-ui.js` (cart/cost lines ~216–225)
  and `js/trip-model.js` (cost calculation). Confirm exact functions in
  source.
- Hotel item shape (from `CLAUDE.md` data model):
  `{id, type:'hotel', name, price, priceType, guests, lat, lng, nights, stayId}`.

### Acceptance criteria
- [ ] Same hotel across 2 nights (or 2 stays with the same `stayId`) →
      **one** line, `× N nights`, correct subtotal.
- [ ] Two different hotels → two separate lines.
- [ ] Trip total is identical to before this change (value unchanged).
- [ ] Golf and POI lines unchanged.
- [ ] An older trip whose hotel items predate `stayId` still groups
      sensibly via the name+coords fallback (no crash, no double-count).

## GOLF-100 — Costs tab: total + per-person columns · blocker · M

### Problem
The Costs tab shows only a single (whole-trip) amount. Owner wants a
per-person view alongside it.

### Requirement
- The Costs tab shows **two amounts**: **Total** and **Per person**.
  - Grand total row: both.
  - Line items: show per-person where it is meaningful (all cost lines
    divide cleanly by group size — see the open question below).
- "Per person" uses the existing **group-size control** already in the
  trip toolbar (find the state field it writes — likely `state.groupSize`
  or similar in `js/trip-model.js`).
- Group size of 1 (or unset) → per-person column equals total.
- Rounding: round each per-person figure to whole currency units; the
  per-person column does **not** need to sum exactly to total ÷ people
  after rounding (a penny of rounding drift is acceptable — do not add a
  reconciliation line).

### Open question for the coding agent to resolve from existing code
GOLF-74 introduced a **per-room / per-person model** for hotels (a room
sleeps `guests` people). Before implementing, check whether the current
cost calc already applies that model:
- **If it does** — per-person should reflect it (a £300 room split by its
  own `guests`, not always by whole-trip group size), and you should match
  that existing logic.
- **If it doesn't** (costs are currently just summed) — implement the
  simple version: **per person = line total ÷ group size**, for every line
  type, and leave a `// TODO GOLF-74 per-room model` comment where the
  hotel split happens.

Whichever you find, state in the PR description which path you took and
why.

### Where
Same renderer as GOLF-116 — `js/trip-ui.js` Costs tab + `js/trip-model.js`
cost calc. Do this in the same pass as GOLF-116.

### Acceptance criteria
- [ ] Costs tab shows a Total and a Per-person amount for the grand total.
- [ ] Changing the toolbar group size updates the per-person figures live
      (or on the next render — match how other toolbar controls behave).
- [ ] Group size 1 → per-person == total.
- [ ] Per-person figures are plausible for a 4-person trip (spot-check one
      golf line, one hotel line, the total).
- [ ] Layout holds on a 360px-wide sidebar — two columns must not overflow
      or clip. Stack or abbreviate if needed, per the design system.

## GOLF-112 — City search: click a result to focus the map · not a blocker · M

### Problem
In the unified search, clicking a geocoded place result **only** adds it to
the trip as a start/free/end stop. There is no way to just look at a place
on the map.

### Requirement
- Clicking a place result **pans/zooms the map** to that location
  (`map.flyTo` / `fitBounds` — match existing camera moves in the app).
- Dropping it into the trip as a stop becomes a **secondary, explicit**
  action — e.g. a small "+ Add stop" button on the result row — not the
  default click.
- Drop a **temporary marker** at the focused place, cleared on the next
  search, on the next manual map interaction, or on Escape. (Owner
  confirmed: marker + view, not view only.)
- Must keep failing soft: the ORS geocoding endpoint intermittently 403s
  (RISK R-1) — the existing "temporarily unavailable" degradation must be
  untouched.
- Works in both the Discover and Itinerary tabs.

### Where
- Unified search + geocode results: `js/trip-ui.js` (~L58–124 build the
  result rows; find the row click handler).
- Geocoding goes through the Cloudflare Worker `geocode` mode — no client
  key, no change needed there.
- Map camera helpers: `js/map.js`.

### Acceptance criteria
- [ ] Search "St Andrews", click the result → map flies there, temp marker
      appears, **trip is unchanged**.
- [ ] The add-as-stop action still exists, is visible, and still works.
- [ ] Temp marker clears on next search / map drag / Escape.
- [ ] Works in Discover and Itinerary tabs.
- [ ] Geocode 403 still shows the existing graceful message, no console
      error.

## GOLF-111 — Course marker redesign (golf ball on a tee) · not a blocker · S

### Design intent
A **golf ball on a tee**. The product owner is supplying a reference PNG
(illustrated golf ball on a red tee, dark outline) — treat it as the
**silhouette / style reference**, not the asset to ship.

### Requirement
- Replace `golfPinSVG()` in `js/map.js` with a **flat inline SVG** that
  reproduces that silhouette: white ball, red tee, dark outline, a couple
  of dimple hints at most. Design at ~**24px**; it must stay crisp and
  legible as a small pin over the new basemap (GOLF-105) and on retina.
- **Keep the state encoding the map has today.** `pinFor(i)` currently
  renders `golfPinSVG(size, rk)` at size **30 if `ranked(i)` else 22**, and
  colour/accent conveys **in-trip / played / want**. The new marker must
  still express:
  - ranked vs unranked (size step is fine to keep);
  - in-trip / played / want (via fill colour or a small accent — expose a
    colour parameter/CSS hook so these are a one-line change, don't
    hard-code white).
- Anchor point at the **base of the tee** (bottom-centre), so the pin
  points at the course location.
- A subtle drop/anchor shadow is fine; **no baked-in gradients** (they
  don't scale or recolour).
- Restyle the cluster badge (`.mcluster` in the CSS) to match the new
  marker's colours if it now looks out of place.
- Do **not** add any raster image file for this. No PNG/JPG marker asset.

### Where
- `golfPinSVG()`, `pinFor(i)` — `js/map.js`.
- `.mcluster` cluster badge — main stylesheet.
- Second map (shared-trip view) in `js/trip-share.js` — if it renders
  course pins, update it too so shared trips match.

### Acceptance criteria
- [ ] New pin renders sharp on retina at both sizes; no raster blur.
- [ ] Ranked vs unranked still visually distinct.
- [ ] In-trip / played / want states still visually distinct.
- [ ] Pin tip sits on the course coordinate (anchor correct).
- [ ] Cluster badges restyled to match if they looked off.
- [ ] Legible over the new basemap (coordinate with whoever does GOLF-105;
      if GOLF-105 isn't merged yet, check against both the current OSM
      tiles and a muted style).
